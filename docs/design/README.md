# Verx 设计

Verx 是一个三端统一的通用软件包管理器：在 Windows、macOS、Linux 上用同一个命令装软件、装依赖。

一句话：`verx` 一个命令，三端一致，用户态安装，干净卸载，可复现。装完的工具直接能跑，装完的库直接能编。

## 解决什么问题

今天装软件是分裂的：Windows 靠 Scoop 思路最干净，macOS 靠 Homebrew 体验最好，Arch 靠 Pacman/Paru 最严谨，但三者互不通用。一个开发者换系统就要重新学一套，软件作者发三端要写三份描述，企业想统一管软件更是各管各的。

Verx 要做的就是把三端收成一个心智：同一个 Registry 概念，同一个包描述，同一个命令。工具和库走同一套：工具装完进 `shims/` 直接跑，库装完留在 `install/` 直接给编译器用。

## 设计立场

- 纯 CLI 程序，不做界面。Verx 自己只有命令行；被安装的软件可以是命令行工具，也可以是桌面应用。
- 默认用户态，不碰系统。不需要管理员权限，装在自己目录下，删就是删目录。
- 借鉴，不模仿。不像 Scoop，也不像 Brew，更不像 Pacman，只把三者被验证过的优点拿过来。
- 描述与实现分离。包描述是声明式的文本，不许是可执行脚本，这是安全底线。
- 文件即状态。不引入嵌入式数据库，目录结构本身就是真相，坏了能扫出来重建。

## 已定事项

主命令只有 `verx`，包描述用 YAML，统一叫 Registry（不分 bucket/tap），hash 强制校验，状态用纯文件。本地目录：`bin/` 只放 Verx 自身，`shims/` 放包入口，`registry/` 放远端 Registry，`install/` 合并实体加状态。工具包和库包走同一个 Registry，靠 `kind: app/lib` 区分：`app` 链进 `shims/`，`lib` 不进 `shims/`、走 `verx env/integrate` 暴露给编译器。细节见各篇。
