# 借鉴：Scoop、Homebrew、Pacman/Paru、vcpkg

看三家的目的不是抄命令，而是看它们各自把哪件事做对了，以及为此付出了什么代价。

## Scoop：把 Windows 下的干净做到了极致

Scoop 的核心想法很简单：软件就放在自己家目录里，不写注册表，不污染系统，卸载就是删文件夹。Registry 就是一个 git 仓库，加 Registry 就是加一个仓库地址，包描述就是一个 JSON，谁都会写。

它做对了三件事。第一，用户态，装软件不需要管理员，这是它体验好的根本。第二，加 Registry 零成本，去中心化做得最彻底。第三，用 shim 解决 Windows 快捷方式问题，不依赖管理员权限也能让命令全局可用。

它的代价也很清楚。只支持 Windows，多端无解。包描述只讲下载地址，依赖关系很弱，装复杂软件会掉链子。去中心化没有质量门，包的好坏全看维护者自觉，hash 校验也不是强制的。

Verx 从 Scoop 拿走用户态、去中心化 Registry、shim 思想，扔掉仅 Windows 和弱依赖、弱校验。

## Homebrew：把好用做到了极致

Homebrew 的核心是两条路都能走：有现成二进制就直接下，没现成就按配方现编。Registry 也是去中心化的 Tap，命令是标杆，search、info、outdated、pin、doctor 整套都很顺。对 macOS 双架构这种脏活处理得很有经验。

它的问题在于配方是 Ruby 代码，功能强但普通人写不了、审不了。默认安装位置和权限历史上反复折腾，多版本共存一直别扭。更新是重量级的，Linux 支持也只是顺带。

Verx 从 Homebrew 拿走双通道、Tap 扩展思想、整套命令动词，扔掉可执行配方和重量级更新，包描述改成谁都能看懂的声明式文本。

## Pacman/Paru：把严谨做到了极致

Pacman 加 AUR 是分层思想的代表：官方管稳，二进制下发；社区管新，源码自编。事务是最严的，下、验、装、钩子一整套，中断能恢复。依赖表达最完整，版本范围、虚拟提供、冲突替换都有。Paru 的交互值得学：构建源码前把脚本摊开给你看，确认了才编。

它的代价是和系统绑死，要 root，只要 Arch 系。AUR 是 shell 脚本，等于默认信任作者，新手很容易中招。而且二进制和源码是两套命令，学习成本是三家里最高的。

Verx 从 Pacman/Paru 拿走事务、分层 Registry、构建前确认，扔掉 root 强依赖和双命令。依赖表达学它，但只取够用的子集。

## Vcpkg：把“给编程语言提供依赖”做成了标配

Vcpkg 要解决的是另一类问题：装软件是给人用的，装依赖是给编译器用的。一个 C/C++ 项目要 `zlib、openssl、boost`，换系统、换架构就得重来一遍。

它做对了四件事。第一，Triplet，把 `x64-windows、x64-linux、arm64-osx` 写进包名，依赖按目标三元组区分，这是 Verx 三端矩阵天然对得上的。第二，Port 即源码配方加二进制缓存，有现成二进制直接下，没有就地编，和 Homebrew 双通道一个思路。第三，Manifest 模式，项目里放一个 `vcpkg.json` 声明要哪些库，可复现。第四，集成，装完的库能被 CMake、MSBuild、pkg-config 直接找到，而不是装完不管用。

它的代价是只管 C/C++，和 Visual Studio 绑得深，Triplet 写法对新手不友好，全局装和项目装两套心智容易混。

Verx 从 vcpkg 拿走 Triplet、双通道、Manifest 可复现、构建集成，扔掉只管 C/C++和 VS 绑定。Verx 的库不只给 C/C++，给任何需要原生依赖的语言用，但第一批只做 C/C++ native 库，保证能落地。

## 一句话总结

Scoop 教会我们轻，Homebrew 教会我们全，Paru 教会我们严，vcpkg 教会我们把依赖交到编译器手里。Verx 的目标是轻和全都要，严作为底线，依赖作为第二条主线。用 Scoop 的方式安放软件，用 Homebrew 的方式组织命令，用 Paru 的方式保证过程可靠，用 Vcpkg 的方式交付库。
